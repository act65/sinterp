# sinterp

An implementation of
[Stochastic interpolants: a unifying framework for flows and diffusions](https://arxiv.org/abs/2303.08797)
(Albergo, Boffi & Vanden-Eijnden): interpolants, stochastic fields and their
losses, noise-data couplings, and exact Gaussian / Gaussian-mixture references.
Integrating a learned field (sampling, densities) is done by the sibling
package [`flow`](../flow/README.md).

| module | contents |
| :--- | :--- |
| `sinterp.interpolants` | the schedules $\alpha, \beta, \gamma$: one- and two-sided interpolants |
| `sinterp.stochasticfield` | `StochasticField` and its parameterisations: which quantities a network learns, how the rest are derived, the losses |
| `sinterp.field_factory` | `field_factory(name, net_constructor, interpolator)` builds a field from a name |
| `sinterp.couplings` | noise-data couplings: independent, Sinkhorn, exact OT, C2OT, per-block C2OT |
| `sinterp.exact_si_gaussian`, `exact_si_gmm`, `exact_ot_gmm` | closed-form fields for Gaussian and Gaussian-mixture endpoints |
| `sinterp.utils` | `get_v`, Gaussian pdf and plotting helpers |

All notation below follows the code; where it differs from the paper this is
said explicitly. Figures are generated by
[`docs/make_figures.py`](../docs/make_figures.py).

## Interpolants

An `Interpolator` defines

$$
x_t = \alpha(t)\,x_0 + \beta(t)\,x_1 + \gamma(t)\,z, \qquad t \in [0, 1],
$$

with $x_0$ the source sample, $x_1$ the target (data) sample and $z$ a standard
Gaussian, all independent unless a coupling pairs $x_0$ with $x_1$. It is
called as `interp(x0, x1, z, t)` and maps over PyTrees (dict-valued blocks are
fine). It also provides `dalphadt`, `dbetadt`, `dgammadt` (by `jax.jacfwd`),
`didt(x0, x1, z, t)` $=\partial_t x_t$, and `deterministic(x0, x1, t)` /
`didt_deterministic(x0, x1, t)`, the same with $z = 0$.

| class | $\alpha(t)$ | $\beta(t)$ | $\gamma(t)$ | notes |
| :--- | :--- | :--- | :--- | :--- |
| `LinearDeterministic` | $1-t$ | $t$ | $0$ | rectified flow / linear flow matching |
| `SquaredDeterministic` | $1-t^2$ | $t^2$ | $0$ | |
| `ConstantNoise(sigma=1e-3)` | $1-t$ | $t$ | $\sigma$ | constant noise level, nonzero at both ends |
| `LinearStochastic` | $1-2t$ for $t<\tfrac12$, else $0$ | $0$ for $t<\tfrac12$, else $2t-1$ | $2t$ for $t<\tfrac12$, else $2(1-t)$ | encoder-decoder: $x_{1/2} = z$ is pure noise |
| `SquaredStochastic` | $(1-2t)^2$ for $t<\tfrac12$, else $0$ | $0$ for $t<\tfrac12$, else $4(t-\tfrac12)^2$ | $4t(1-t)$ | encoder-decoder |
| `TrigonometricStochastic` | $\sqrt{1-\gamma^2}\cos(\tfrac{\pi t}{2})$ | $\sqrt{1-\gamma^2}\sin(\tfrac{\pi t}{2})$ | $\sqrt{2t(1-t)}$ | $\alpha^2+\beta^2+\gamma^2 = 1$ |
| `LinearVPStochastic` | $1-t$ | $t$ | $\sqrt{2t(1-t)}$ | straight mean path, $\alpha^2+\beta^2+\gamma^2 = 1$ |
| `TrigonometricVPStochastic(sigma=0.5)` | $\sqrt{1-\gamma^2}\cos(\tfrac{\pi t}{2})$ | $\sqrt{1-\gamma^2}\sin(\tfrac{\pi t}{2})$ | $\sigma\sin(\pi t)$ | $\alpha^2+\beta^2+\gamma^2 = 1$ |
| `EncodingDecodingStochastic` | $\cos^2(\pi t)$ for $t<\tfrac12$, else $0$ | $0$ for $t<\tfrac12$, else $\cos^2(\pi t)$ | $\sin^2(\pi t)$ | encoder-decoder, $x_{1/2} = z$ |
| `LowNoiseEncodingDecodingStochastic` | $\cos^4(\tfrac{\pi t}{2})$ | $\sin^4(\tfrac{\pi t}{2})$ | $\tfrac12\sin^2(\pi t)$ | |
| `OneSidedLinear` | $0$ | $t$ | $1-t$ | one-sided: $x_t = (1-t)\,z + t\,x_1$; `x0` is ignored |
| `OneSidedSBDM` | $0$ | $t$ | $\sqrt{1-t^2}$ | one-sided, $\beta^2+\gamma^2 = 1$ |

*Two-sided* interpolants bridge two arbitrary distributions ($x_0$ at $t=0$,
$x_1$ at $t=1$) and add noise only in between. *One-sided* interpolants have
$\alpha \equiv 0$: the source is the Gaussian $z$ itself, as in flow matching
and diffusion models; with them the `x0` argument is ignored. The
encoder-decoder interpolants pass through pure noise at $t = \tfrac12$, so
$x_0$ and $x_1$ never appear together. `TrigonometricStochastic`,
`LinearVPStochastic` and `TrigonometricVPStochastic` keep
$\alpha^2+\beta^2+\gamma^2 = 1$ (variance preserving for unit-variance,
independent endpoints). Some schedules have infinite derivatives at an endpoint
(`TrigonometricStochastic`, `LinearVPStochastic` at $t = 0, 1$; `OneSidedSBDM`
at $t = 1$), so sample $t$ from an open interval.

## Stochastic fields

### Quantities

A `StochasticField` exposes six functions of $(x_t, t)$, all conditional
expectations given $x_t = x$:

| method | quantity | definition in the code |
| :--- | :--- | :--- |
| `get_denoiser_eta0` | $\eta_0$ | $E[x_0 \mid x_t = x]$ |
| `get_denoiser_eta1` | $\eta_1$ | $E[x_1 \mid x_t = x]$ |
| `get_denoiser_etaz` | $\eta_z$ | $E[z \mid x_t = x]$ |
| `get_velocity_b` | $b$ | $\dot\alpha\,\eta_0 + \dot\beta\,\eta_1 + \dot\gamma\,\eta_z = E[\partial_t x_t \mid x_t = x]$, the velocity of the probability-flow ODE $\dot X = b(X, t)$ |
| `get_velocity_v` | $v$ | $\dot\alpha\,\eta_0 + \dot\beta\,\eta_1 = b - \dot\gamma\,\eta_z$, the part of $b$ not due to the noise |
| `get_score_s` | $s$ | $\nabla_x \log p(t, x) = -\eta_z / \gamma$ |

They are tied together by $x = \alpha\,\eta_0 + \beta\,\eta_1 + \gamma\,\eta_z$
(take $E[\cdot \mid x_t = x]$ of the interpolant), so $v = b + \gamma\dot\gamma\,s$
(this is `sinterp.utils.get_v`). Any two of them determine the rest where the
corresponding linear system is invertible. The forward SDE drift used for sampling
is $b + \epsilon\,s$ (see `flow.Process`); $v$ is not a drift (earlier versions
of this README called it one).

### Losses

Each loss takes one sample `(x0, x1, z, t)` (vmap over a batch), with
$x_t$ = `interp(x0, x1, z, t)`:

| loss | objective |
| :--- | :--- |
| `loss_b` | $\lVert b(x_t, t) - \partial_t x_t \rVert^2$, $\partial_t x_t = \dot\alpha x_0 + \dot\beta x_1 + \dot\gamma z$ |
| `loss_v` | $\lVert v(x_t, t) - (\dot\alpha x_0 + \dot\beta x_1) \rVert^2$ |
| `loss_eta0`, `loss_eta1`, `loss_etaz` | $\lVert \eta_0(x_t, t) - x_0 \rVert^2$, $\lVert \eta_1(x_t, t) - x_1 \rVert^2$, $\lVert \eta_z(x_t, t) - z \rVert^2$ |
| `loss_s` | $\tfrac12\lVert s(x_t, t) \rVert^2 + \gamma^{-1}\, s(x_t, t) \cdot z$ (denoising score matching; minimiser $s = -\mathbb{E}[z \mid x_t]/\gamma$); $0$ where $\lvert\gamma\rvert \le 10^{-5}$ |

(Squared norms are means over elements, summed over PyTree leaves.) Each class's
`total_loss` is the sum of the losses of the quantities it learns.

### Parameterisations

| class | learns (networks) | `total_loss` | derives | singular where (derived values returned as 0) |
| :--- | :--- | :--- | :--- | :--- |
| `TwoSidedField_v_etaz` | $v$, $\eta_z$ | `loss_v + loss_etaz` | $b = v + \dot\gamma\eta_z$; $s = -\eta_z/\gamma$; $(\eta_0, \eta_1)$ from $\alpha\eta_0+\beta\eta_1 = x-\gamma\eta_z$, $\dot\alpha\eta_0+\dot\beta\eta_1 = v$ | $s$: $\gamma = 0$. $\eta_0, \eta_1$: $\dot\alpha\beta - \dot\beta\alpha = 0$ |
| `TwoSidedField_b_s` | $b$, $s$ | `loss_b + loss_s` | $\eta_z = -\gamma s$; $v = b + \gamma\dot\gamma s$; $(\eta_0, \eta_1)$ as above | $\eta_0, \eta_1$: $\dot\alpha\beta - \dot\beta\alpha = 0$ |
| `TwoSidedField_x0_x1` | $\eta_0$, $\eta_1$ | `loss_eta0 + loss_eta1` | $v = \dot\alpha\eta_0 + \dot\beta\eta_1$; $\eta_z = (x - \alpha\eta_0 - \beta\eta_1)/\gamma$; $b = v + \dot\gamma\eta_z$; $s = -\eta_z/\gamma$ | $\eta_z, s$: $\gamma = 0$ |
| `TwoSidedField_b_eta1` | $b$, $\eta_1$ | `loss_b + loss_eta1` | $(\eta_0, \eta_z)$ from $\alpha\eta_0+\gamma\eta_z = x-\beta\eta_1$, $\dot\alpha\eta_0+\dot\gamma\eta_z = b-\dot\beta\eta_1$; $v$; $s = -\eta_z/\gamma$ | $\eta_0, \eta_z, s$: $\alpha\dot\gamma - \dot\alpha\gamma = 0$ (e.g. wherever $\alpha \equiv 0$) |
| `OneSidedField_b` | $b$ | `loss_b` | $\eta_0 = 0$; $(\eta_z, \eta_1)$ from $\gamma\eta_z+\beta\eta_1 = x$, $\dot\gamma\eta_z+\dot\beta\eta_1 = b$; $s = -\eta_z/\gamma$; $v = \dot\beta\eta_1$ | $\dot\gamma\beta - \dot\beta\gamma = 0$ |
| `OneSidedField_eta1` | $\eta_1$ | `loss_eta1` | $\eta_0 = 0$; $\eta_z = (x - \beta\eta_1)/\gamma$; $b = \dot\gamma\eta_z + \dot\beta\eta_1$ (evaluated at $\min(t, 0.99)$, with $\gamma$ floored at $10^{-3}$); $s = -\eta_z/\gamma$; $v = \dot\beta\eta_1$ | $\eta_z, s$: $\lvert\gamma\rvert \le 10^{-4}$ |

The one-sided classes assume $\alpha \equiv 0$ and are only meaningful with the
one-sided interpolants. (`OneSidedFlow` is a stub that only sets $\eta_0 = 0$.)
The tolerances are $\lvert\det\rvert \le 10^{-9}$ for the linear solves and
$\lvert\gamma\rvert \le 10^{-5}$ for divisions by $\gamma$ unless noted.

Below, each class is given the *exact* quantities it learns (closed-form
Gaussian-mixture fields in place of the networks), and its own methods derive
the rest. Learned panels have an orange frame.

![two-sided fields](../docs/images/fields/two_sided.png?raw=true)

![one-sided fields](../docs/images/fields/one_sided.png?raw=true)

Whether a class can return $b$ (needed by an ODE sampler) and $s$ (needed by an
SDE sampler) depends on the interpolant: the error of the derived $b$ and $s$
for every pair, again with exact learned inputs.

![recoverability matrix](../docs/images/fields/recoverability.png?raw=true)

Reading the matrix (exact inputs; with networks, errors add to these):

- Every class returns $b$ for every interpolant, so any of them can drive an ODE
  sampler. The two-sided classes also work with one-sided interpolants.
- With $\gamma \equiv 0$ (`LinearDeterministic`, `SquaredDeterministic`) the score
  cannot be derived ($s = -\eta_z/\gamma$ is masked to 0). `TwoSidedField_b_s`
  represents $s$ directly, but `loss_s` is 0 when $\lvert\gamma\rvert \le 10^{-5}$,
  so it cannot be trained there either. Use a stochastic interpolant for SDE
  sampling.
- Tiny $\gamma$ (`ConstantNoise`, $\sigma = 10^{-3}$) costs the classes that
  divide by $\gamma$ (`x0_x1`, `b_eta1`) a few percent of $s$.
- `TwoSidedField_b_eta1` loses $s$ wherever $\alpha = \dot\alpha = 0$: for
  $t > \tfrac12$ in the encoder-decoder interpolants (`LinearStochastic`,
  `SquaredStochastic`, `EncodingDecodingStochastic`) and everywhere for one-sided
  ones. With `TrigonometricVPStochastic` its system becomes ill-conditioned as
  $\alpha \to 0$ near $t = 1$ and the derived $s$ is wrong rather than 0.

Which to use:

| goal | suggested class |
| :--- | :--- |
| noise to data, ODE sampling (flow matching) | `OneSidedField_b` with `OneSidedLinear` |
| noise to data, predict clean data | `OneSidedField_eta1` (its $b$ is clamped at $t = 0.99$) |
| bridge between two distributions, ODE and SDE | `TwoSidedField_v_etaz` or `TwoSidedField_b_s` with a stochastic interpolant such as `LinearVPStochastic` |
| predict both endpoints (e.g. for guidance on $E[x_1 \mid x_t]$) | `TwoSidedField_x0_x1` with $\gamma > 0$ |
| $b$ plus a data prediction $\eta_1$ | `TwoSidedField_b_eta1`, with an interpolant whose $\alpha$ does not vanish before $t = 1$ |

### Building fields

`field_factory(field_name, net_constructor, interpolator)` instantiates any of
the six classes above by name. `net_constructor(n_outputs)` must return a
single network for `n_outputs=1` (one-sided classes) and, for `n_outputs=2`
(two-sided classes), a tuple `(net, get_first, get_second)` where the getters
split the network's output into the two learned quantities.
`make_default_net_constructor(init_net)` builds such a constructor from
`init_net(n_outputs) -> eqx.Module`, splitting every output leaf in half along
its last axis (so `init_net(2)` must output twice the data dimension). Inputs
and outputs may be PyTrees, e.g. dicts of blocks.

## Couplings

A coupling re-pairs a minibatch before the interpolant is formed:

```python
x0, x1_coupled, c0, c1_coupled, extra = coupling(key, x0, x1, c0=None, c1=None, **extra)
```

returns `x1` (and `c1`, and any extra PyTrees) re-ordered or re-weighted so that
row `i` of the output is paired with row `i` of `x0`. In the examples below
`x0` is the noise and `x1` the data, except for `C2OTCoupling`, whose
docstring takes the data first (`x0` = data with conditions `c0`, `x1` =
noise).

| class | pairing | output |
| :--- | :--- | :--- |
| `IndependentCoupling()` | random permutation: $p(x_0, x_1) = p(x_0)\,p(x_1)$ | a permutation of `x1` |
| `SinkhornCoupling(epsilon=0.1, n_iters=100, beta=0.0)` | entropic OT plan $P$ with squared-Euclidean cost (fixed-iteration log-domain Sinkhorn by default); with `c0, c1` and `beta > 0` the cost adds $\beta\lVert c_0 - c_1\rVert^2$ | the **barycentric projection** $x_1^{\text{coupled}}[i] = \sum_j P_{ij} x_1[j] / \sum_j P_{ij}$: a weighted average of data rows, not a data row |
| `ExactOTCoupling(epsilon=1e-2, n_iters=1000)` | the same with smaller $\epsilon$ (OTT solver with its convergence check) | barycentric projection; close to, but not exactly, a permutation |
| `ExactConditionalCoupling(beta=100, epsilon=1e-3)` | `ExactOTCoupling` with a heavily weighted condition term | barycentric projection |
| `C2OTCoupling(w=None, target_ratio=0.01, cond_dist='sqeuclidean')` | exact one-to-one matching (Hungarian, `scipy.optimize.linear_sum_assignment`) with cost $\lVert x_{0,i} - x_{1,j}\rVert^2 + w\, d(c_{0,i}, c_{1,j})$; `c1 = c0` unless given | a permutation of `x1` |

`C2OTCoupling` ([Cheng & Schwing, ICCV 2025](https://arxiv.org/abs/2503.10636))
is condition-aware OT. Without conditions, or with `w=0`, it is plain
minibatch exact OT. With `w=None` the weight is chosen per batch (closed form
of the paper's adaptive rule): the smallest $w$ for which the fraction of
pairs $(i, j)$ with $\text{cost}_{ij} \le \text{cost}_{ii}$ is at most
`target_ratio`. `cond_dist` is `'sqeuclidean'`, `'cosine'` (the paper's choice
for embeddings) or `'discrete'` (matches only between equal conditions).
`matching(x0, x1, c0, c1)` returns the permutation and the $w$ used.

![unconditional couplings](../docs/images/couplings/unconditional.png?raw=true)

**Conditional models.** OT pairs noise with data by distance, so for a model
of $x \mid c$ the noise it is trained from depends on $c$; at sampling time the
noise is drawn independently of $c$. C2OT only re-orders noise between rows
with similar conditions:

![conditional couplings](../docs/images/couplings/conditional.png?raw=true)

With a condition that takes only a few values (here two), most pairs with equal
conditions can never be excluded and the adaptive target is unreachable. The rule
then returns $w = \infty$ and matches within equal conditions exactly, the same
matching as `cond_dist='discrete'`.

**Per-block coupling.** For dict-valued data whose blocks are modelled by
conditional fields (a block-triangular, or "dynamic", flow),
`C2OTCoupling().couple_blocks(key, x_dict, e_dict, conditions)` couples each
block's noise `e_dict[v]` to `x_dict[v]` separately, with the blocks
`conditions[v]` (e.g. its parents) as the condition, and returns the
re-ordered noise dict. Taken in topological order this is a minibatch
Knothe-Rosenblatt coupling, which makes the block-triangular flow consistent
(see [structflow](https://github.com/act65/structflow)). Coupling the full
vector jointly instead (Sinkhorn or exact OT) makes the training noise of a
child block correlated with its parent:

![joint vs per-block couplings](../docs/images/couplings/blocks.png?raw=true)

Use independent pairing, `C2OTCoupling`, or `couple_blocks` whenever a model is
conditioned on part of its input.

## Exact references

- `exact_si_gmm.construct_p_b_s(interp, m0s, m1s, c0s, c1s, w0s, w1s, ce=None)`:
  density $p(z, t)$, velocity $b(z, t)$ and score $s(z, t)$ of $x_t$ when
  $x_0$ and $x_1$ are independent Gaussian mixtures (lists of means,
  covariances, weights; any dimension and number of components) and $z \sim
  N(0, ce)$. Each pair of components gives a Gaussian with mean
  $m_t = \alpha m_0 + \beta m_1$ and covariance
  $C_t = \alpha^2 C_0 + \beta^2 C_1 + \gamma^2 C_e$; $b = \dot m_t + \tfrac12 \dot C_t C_t^{-1}(z - m_t)$
  and $s = -C_t^{-1}(z - m_t)$ per pair, combined with posterior weights
  (a softmax of log-densities, so the fields stay finite far from every component).
- `exact_si_gaussian.construct_p_b_s(m1, m2, c1, c2, interp)`: the single
  Gaussian case; returns `(p, v, s)` with covariance
  $\alpha^2 C_1 + \beta^2 C_2 + \gamma^2 I$ (`v` is the drift $b$, which equals the
  probability-flow velocity only when $\gamma \equiv 0$).
- `exact_ot_gmm.construct_optimal_transport(m0s, m1s, c0s, c1s, w0s, w1s, epsilon=0.1)`:
  an OT-style reference: components are paired by an entropic OT plan on their
  exact $W_2$ costs, and each pair moves along its McCann ($W_2$) geodesic.

The figures in this README are all computed from `exact_si_gmm` (the
denoisers $\eta$ from the same per-component posteriors).
